# 故事生成器第一版设计文档

## 产品定位

故事生成器是一款网页端文字互动冒险游戏。玩家创建一本由 AI 生成的短篇小说，并在其中扮演自己设定的角色。除玩家输入的世界观、角色设定和行动外，故事正文、NPC、线索、冲突、抉择点和结局均由玩家接入的 AI 大模型生成。

第一版定位为沉浸式短篇 AI 互动小说 MVP。目标是验证“自由输入行动 + AI 中等约束裁判 + 小说式剧情推进”是否有足够的沉浸感和可玩性。

第一版不做平台化功能、社区、账号、云同步、复杂数值战斗、章节树编辑器和长篇连载。后续版本再扩展中篇章节和长篇连载。

## 第一版体验目标

玩家流程：

1. 进入创建故事页。
2. 输入故事标题、题材风格、世界观设定、玩家角色设定。
3. 配置自己的 AI 模型接口。
4. 进入独立的游戏阅读页。
5. AI 生成开篇、NPC、冲突和第一个抉择点。
6. 玩家在底部输入框输入角色行动。
7. AI 判断行动是否符合世界规则、角色能力和当前处境。
8. AI 根据裁判结果续写小说并更新状态。
9. 重复 10 到 20 回合后生成结局。
10. 玩家可以保存、继续或导出完整故事文本。

## 页面设计

第一版使用两个独立网页，而不是单页中的两个区域。

### 创建故事页

路径建议：`/create`

职责：

- 收集故事标题。
- 收集题材与风格。
- 收集世界观设定。
- 收集玩家角色设定。
- 收集 AI 模型配置。
- 创建故事后跳转到游戏阅读页。

创建页采用极简表单。它只服务开始前设定，不承载游戏中的阅读体验。

### 游戏阅读页

路径建议：`/play/:storyId`

职责：

- 展示当前故事标题和回合进度。
- 中间主体展示小说正文。
- 底部固定输入框，玩家输入角色行动。
- 侧边栏展示角色卡、NPC、线索、世界规则、故事进度和危险度。
- 每轮行动后追加新的小说内容并更新状态。

阅读页交互方式接近日常 AI 对话，但正文呈现必须像小说，不使用聊天气泡。正文应包含章节标题、段落、对话、环境描写和抉择点。

## 视觉原则

- 采用极简风格。
- 强调留白、文字层级和阅读舒适度。
- 不做复杂游戏 HUD。
- 模型配置、系统细节和隐藏裁判尽量不打扰阅读。
- 侧边栏承担状态信息，主区域只服务小说阅读和行动输入。

## AI 系统

第一版采用单次模型调用完成行动裁判、剧情续写和状态更新。后续复杂化后可拆成多次调用。

### 行动裁判

玩家输入行动后，AI 先判断行动是否合理。裁判分为四类：

- `allowed`：行动符合角色能力、世界规则和当前处境。
- `allowed_with_cost`：行动可以执行，但带来风险、消耗、暴露或关系变化。
- `failed_forward`：行动失败，但剧情继续推进并产生后果。
- `rejected`：行动严重违背世界观、角色能力或游戏边界，需要玩家重写。

明显不合理行为不能直接被 AI 接住。例如普通侦探不能突然使用未设定的雷电魔法摧毁城市。

### 剧情生成

AI 每轮生成：

- 小说正文。
- 新的抉择点。
- NPC 变化。
- 线索变化。
- 世界记忆变化。
- 危险度变化。
- 结局进度变化。

玩家只看到小说正文、抉择点和必要提示。状态更新保存在结构化数据中。

### 结构化输出

模型输出应尽量要求 JSON 结构，前端只展示 `story_text` 和 `choice_point`。

示例：

```json
{
  "verdict": "allowed_with_cost",
  "verdict_reason": "询问守夜人符合角色能力，但会提高对方戒备。",
  "story_text": "守夜人的手指收紧了……",
  "choice_point": "你要继续追问，还是转而观察钟楼内部？",
  "state_patch": {
    "npc_attitude": {
      "守夜人": "更加戒备"
    },
    "clues_added": ["父亲曾在钟楼留下记录"],
    "danger_level": "medium",
    "ending_progress_delta": 0.08
  }
}
```

输出格式错误时，系统应重试或要求模型修复 JSON。

## 数据结构

### StoryConfig

保存创建故事时的设定。

```json
{
  "id": "story-id",
  "title": "雨夜钟楼",
  "genre": "悬疑、低魔",
  "style": "严肃、短篇",
  "world_setting": "一座被雨季封锁的旧城……",
  "player_character": {
    "name": "林舟",
    "identity": "档案修复师",
    "goal": "查清父亲失踪真相",
    "abilities": ["观察", "推理", "档案修复"],
    "weaknesses": ["体力较弱"]
  },
  "rules": ["禁止公开谈论失踪案", "午夜钟声会改变部分记忆"]
}
```

### GameState

保存当前游戏局势。

```json
{
  "story_id": "story-id",
  "turn": 3,
  "max_turns": 15,
  "current_location": "旧城钟楼",
  "danger_level": "medium",
  "ending_progress": 0.28,
  "player_status": ["紧张", "轻微疲惫"],
  "npc_registry": [],
  "clues": [],
  "world_memory": []
}
```

### TurnLog

保存每轮玩家行动和 AI 结果。

```json
{
  "story_id": "story-id",
  "turn": 3,
  "player_action": "我压低声音，询问他为什么认识我父亲。",
  "verdict": "allowed_with_cost",
  "story_text": "守夜人的手指收紧了……",
  "choice_point": "你要继续追问，还是转而观察钟楼内部？",
  "state_patch": {},
  "created_at": "2026-05-12T12:00:00+08:00"
}
```

## 存档方案

第一版使用浏览器本地存储：

- `localStorage` 保存轻量故事索引和当前故事 ID。
- `IndexedDB` 保存完整故事配置、游戏状态和回合日志。

第一版不做账号、云同步和复杂存档槽。

后续 Steam 桌面版可以迁移为本地文件存档：

```text
AppData/StoryGenerator/saves/story-id.json
```

## 技术路线

推荐技术栈：

- React
- TypeScript
- Vite
- Zustand
- IndexedDB
- OpenAI-compatible API client

第一版可以不做传统后端。玩家在网页里配置自己的模型接口，系统通过 OpenAI-compatible 格式发送请求。

浏览器直连模型服务可能遇到 CORS 问题，因此架构中需要预留 AI 代理层接口。网页 MVP 可以先支持浏览器直连；未来 Steam 版通过 Tauri 本地代理解决 CORS 和 API Key 管理问题。

推荐目录结构：

```text
src/
  pages/
    CreateStoryPage.tsx
    GameReaderPage.tsx
  components/
    NovelView.tsx
    ActionInput.tsx
    SidebarStatePanel.tsx
    ModelConfigForm.tsx
  game/
    promptBuilder.ts
    aiClient.ts
    stateReducer.ts
    saveStore.ts
    types.ts
  storage/
    indexedDb.ts
```

## Steam 迁移

后续上 Steam 时推荐使用 Tauri 封装网页应用。

迁移时主要替换：

- `IndexedDB` 到本地文件存档。
- 浏览器直连 AI 到 Tauri 本地代理。
- Web 路由到桌面窗口路由。

核心游戏逻辑、Prompt 构建、状态结构和大部分 UI 可继续复用。

Steam 版可增加：

- 本地文件存档。
- Steam 云存档。
- 成就系统。
- 模板故事包。
- 本地模型代理。
- 更安全的 API Key 管理。

## 第一版验收标准

- 玩家能从零创建一个故事。
- 玩家能接入自己的模型。
- AI 能生成符合设定的开篇。
- 玩家能自由输入行动。
- 明显不合理行动会被拦截或要求重写。
- 合理行动会产生有后果的剧情推进。
- NPC、线索和危险度会随剧情变化。
- 一局能在 10 到 20 回合内自然结束。
- 刷新页面后能继续。
- 整局故事可以导出为小说文本。

## 后续扩展路线

第二阶段增加中篇章节：

- 章节结构。
- 每章目标。
- 章节摘要。
- 章节结尾钩子。
- 跨章节 NPC 和线索继承。

第三阶段增加长篇连载：

- 自动剧情摘要。
- 长期记忆库。
- 角色关系网。
- 世界事件时间线。
- 伏笔回收列表。
- 玩家行为偏好分析。

长篇时 Prompt 上下文应分层组织：

```text
当前回合上下文
  + 最近 3-5 回合原文
  + 当前章节摘要
  + 全局故事摘要
  + 角色/NPC/线索结构化档案
  + 与当前场景相关的长期记忆
```
